# Phase 1 자동 테스트 시나리오

이 문서는 `Client/tests/app.test.cjs`에서 자동으로 검증하는 동작을 기록한다. 각 시나리오는 [기능 요구사항](./feature-requirements.md)과 [Phase 1 개발 로드맵](./phase-1.md)의 규칙을 따른다. 시간은 테스트를 실행하는 환경의 현지 시간이다.

프로젝트 루트에서 다음 명령을 실행한다.

```powershell
node --test
```

GitHub에서는 PR을 열거나 업데이트할 때 전체 테스트를 실행하고 결과를 PR의 Checks에 표시한다. 테스트가 실패하면 실패 원인과 영향을 확인하고 수정 방안을 사용자에게 설명해 검토받은 뒤 수정한다. 수정 후 관련 테스트와 전체 테스트를 다시 실행한다.

테스트는 Node.js에서 저장소와 화면 요소를 대체해 앱 코드를 실행한다. 실제 브라우저의 입력·렌더링, 서비스 워커와 오프라인 실행, iPhone 홈 화면 설치는 아래 자동 테스트의 범위에 포함되지 않는다.

## 루틴의 반복과 완료 기록

관련 요구사항은 `RT-01`부터 `RT-03`, `GR-01`과 `GR-02`다.

**Given** 월요일에 월·수·금 루틴, 월요일 루틴, 화요일 루틴이 이 순서로 저장되어 있다. 첫 루틴의 시간 문구는 두 번째보다 늦다.

**When** 월요일 목록을 열고 첫 루틴을 두 번 완료한 뒤, 화요일과 수요일 목록을 차례로 확인하고 수요일에 같은 루틴을 완료한다.

**Then** 월요일에는 해당 요일의 루틴이 등록 순서로 표시되고 화요일 루틴은 표시되지 않는다. 월요일의 두 번의 완료 요청에서 보상은 한 번만 지급된다. 화요일에는 화요일 루틴이 표시되고 첫 루틴은 표시되지 않는다. 수요일에는 첫 루틴이 미완료로 다시 표시되며, 완료하면 새로운 보상으로 먹이 1개를 받는다.

테스트 이름은 `요일에 맞는 루틴을 등록 순서로 표시하고 완료를 날짜별로 기록한다`다.

## 할 일 마감 시각의 보상 경계

관련 요구사항은 `PL-01`, `PL-06`, `GR-01`과 `GR-02`다.

**Given** 당일 오전 11시가 마감인 미완료 할 일이 있고, 아직 보상을 받은 적이 없다.

**When** 해당 할 일을 각각 마감 1밀리초 전, 정각, 1밀리초 후에 완료한다. 각 경우에서 완료 요청을 두 번 보낸다.

**Then** 세 경우 모두 완료 시각이 저장된다. 마감 직전에 완료한 경우에만 첫 보상인 알을 받는다. 정각과 그 이후에는 보상이 없다. 같은 할 일에 대한 두 번째 요청은 보상을 중복 지급하지 않는다.

세 테스트 이름은 `마감 직전에 완료한 할 일의 보상 판정`, `마감 정각에 완료한 할 일의 보상 판정`, `마감 이후에 완료한 할 일의 보상 판정`이다.

## 할 일 정렬과 지난 기록 조회

관련 요구사항은 `PL-03`과 `PL-05`다.

**Given** 어제, 오늘, 내일 마감인 할 일이 있고 현재 시각은 오늘 할 일의 마감 시각 이후다.

**When** 데일리 할 일 목록과 어제 날짜의 캘린더를 확인한 뒤, 날짜를 다음 날로 바꾸어 데일리를 다시 연다.

**Then** 오늘의 할 일은 내일의 할 일보다 먼저 표시되고 어제의 할 일은 데일리에 표시되지 않는다. 어제의 할 일은 캘린더에서 조회된다. 다음 날에는 오늘 마감이었던 할 일이 데일리에서 사라지고 내일 마감이었던 할 일은 남는다.

테스트 이름은 `할 일은 마감순으로 표시하고 지난 날짜는 달력에 보관한다`다.

## 알 부화와 먹이 기록 복원

관련 요구사항은 `GR-01`부터 `GR-03`이다.

**Given** 보상과 먹이가 없는 상태에서 오늘의 루틴과 마감 전 할 일 두 개를 준비한다.

**When** 루틴을 완료하고 먹이 없이 부화를 시도한다. 첫 할 일을 완료해 받은 먹이로 알을 부화시키고, 두 번째 할 일을 완료해 받은 먹이를 몬스터에게 준 뒤 먹이가 없는 상태에서 다시 먹이 주기를 시도한다. 이후 저장된 데이터로 앱을 다시 연다.

**Then** 첫 완료로 알을 받고 먹이가 없을 때는 부화하지 않는다. 먹이 1개를 사용해 부화하면 몬스터에게 먹인 횟수는 0회다. 이후 먹이 1개를 주면 잔량은 0개, 먹인 횟수는 1회가 된다. 먹이가 없을 때 추가로 먹일 수 없으며 다시 연 화면에도 먹인 횟수 1회가 표시된다.

테스트 이름은 `알 획득, 부화, 먹이 주기와 새로고침 후 복원을 확인한다`다. 앱을 다시 여는 동작은 동일한 저장 데이터를 새 테스트 인스턴스에 전달해 확인한다.

## 저장 실패 시 완료와 보상

관련 요구사항은 `RT-03`, `GR-01`과 `GR-02`다.

**Given** 오늘 표시되는 미완료 루틴이 저장되어 있고, 이후 브라우저 저장 작업이 실패한다.

**When** 루틴을 완료한다.

**Then** 저장된 완료 기록과 보상은 모두 변경되지 않는다. 화면에는 저장 실패 메시지가 보이고 루틴은 완료 상태로 표시되지 않는다.

테스트 이름은 `저장 실패 시 완료와 보상이 둘 다 반영되지 않는다`다.

## 입력값에 포함된 HTML 특수 문자

관련 요구사항은 `RT-01`과 `RT-02`다.

**Given** 루틴 내용에 `<img onerror=alert(1)>`처럼 HTML 태그 형태의 문자가 들어 있다.

**When** 오늘의 루틴 목록을 표시한다.

**Then** 입력값의 꺾쇠가 HTML 엔티티로 변환되며 입력값이 실제 이미지 태그로 삽입되지 않는다.

테스트 이름은 `사용자 입력의 HTML 특수 문자를 화면에 안전하게 표시한다`다.

## 오프라인 캐시 업데이트

**Given** 새 서비스 워커가 설치되고 기존 버전의 앱 캐시가 있다.

**When** 새 리소스의 저장에 성공한다.

**Then** 새 서비스 워커가 활성화를 요청하고, 이전 앱 캐시만 정리한 뒤 열린 창을 제어한다. 요청은 현재 버전의 캐시에서 조회한다. 테스트 이름은 `새 리소스를 모두 저장한 뒤 업데이트를 활성화한다`, `활성화 시 이전 앱 캐시만 정리하고 현재 창에 적용한다`, `요청은 현재 버전 캐시에서 조회한다`다.

**Given** 새 리소스를 캐시에 저장하는 과정이 실패한다.

**When** 서비스 워커 설치가 실패한다.

**Then** 새 서비스 워커는 활성화를 요청하지 않는다. 테스트 이름은 `리소스 저장 실패 시 업데이트를 활성화하지 않는다`다.

## Phase 2 저장과 완료 취소

**Given** 일정 목록이 없는 Phase 1 데이터와 보상·몬스터 상태가 저장되어 있다.

**When** 앱을 열어 일정을 저장한다.

**Then** 일정이 추가되고 기존 보상, 먹이와 몬스터 상태가 유지된다. 테스트 이름은 `Phase 1 데이터에 일정 목록이 없어도 기존 보상과 육성을 보존한다`다.

**Given** 월말에 시작해 다음 날 자정에 끝나는 시간 지정 일정과 그 다음 날이 종료일인 종일 일정이 있다.

**When** 각 날짜의 일정 표시 여부를 확인한다.

**Then** 자정에 끝나는 시간 지정 일정은 종료일을 제외하고, 종일 일정은 종료일을 포함한다. 테스트 이름은 `시간 지정 일정의 자정 종료와 종일 일정의 종료일을 구분한다`다.

**Given** 루틴과 할 일을 완료해 받은 먹이로 알을 부화시켰다.

**When** 각각 완료를 취소한 후 다시 완료한다.

**Then** 기존 보상이 중복 지급되지 않고 부화 상태와 먹이 잔량이 유지된다. 테스트 이름은 `완료를 취소하고 다시 완료해도 기존 보상을 중복 지급하지 않는다`다.

**Given** 완료한 루틴과 지급된 보상이 저장되어 있고 저장이 실패한다.

**When** 완료를 취소한다.

**Then** 저장된 완료와 보상이 유지되고 오류 메시지가 표시된다. 테스트 이름은 `완료 취소 저장 실패 시 완료와 보상을 유지한다`다.
