# TimeManager Phase 1 개발 로드맵

첫 프로토타입의 목표는 사용자가 루틴을 체크하거나 할 일을 마감 전에 완료해 보상을 받고, 그 보상으로 알을 부화시킨 뒤 몬스터에게 먹이를 줄 수 있게 하는 것이다. iPhone과 Windows PC의 브라우저에서 이 흐름을 사용할 수 있고, 진행 상태는 각 기기에 저장한다.

상위 요구사항은 [기능 요구사항](./feature-requirements.md)을 참조한다. 아래의 보상 수량, 부화 조건, 완료 처리 방식은 Phase 1에 적용한다.

## Phase 1 범위

| 화면 | 제공 기능 |
| --- | --- |
| 데일리 | 상단에 알 또는 몬스터와 먹이 보유량을 표시한다. 아래의 **루틴**과 **할 일** 탭에서 오늘의 루틴을 추가·완료하고, 마감이 가까운 할 일을 완료한다. |
| 캘린더 | 월을 이동하고 날짜를 선택해 그날 마감인 할 일을 등록·조회한다. 지난 할 일과 완료 상태도 조회한다. |

하단 메뉴는 **데일리**와 **캘린더** 두 개다. 시간 범위 일정과 종일 일정, 루틴·할 일의 수정과 삭제, 완료 취소, 예약 알림, 기기 간 동기화, 추가 몬스터와 성장 단계는 후속 단계에서 다룬다.

## 개발 순서

### 1 화면 틀과 기기 저장 기반

- 모바일과 PC에서 데일리·캘린더를 전환할 수 있는 화면 틀을 만든다. 데일리에는 루틴·할 일 탭과 키우기 영역을 둔다. `UI-01`, `UI-02`
- 루틴의 반복 설정과 날짜별 완료 기록, 할 일의 마감과 완료 시각, 보상 지급 기록, 먹이 수량과 육성 상태를 같은 기기에서 다시 읽을 수 있게 설계한다. Phase 1은 브라우저의 로컬 저장소를 사용하고, 완료 기록과 보상처럼 함께 바뀌는 값은 한 번의 저장으로 반영한다.
- 오늘 날짜와 요일, 마감 시각은 기기의 현지 시간을 기준으로 처리한다. 날짜가 바뀐 뒤 앱을 열거나 다시 돌아오면 루틴 목록과 할 일 표시 여부를 갱신한다.
- **완료 기준** — 두 화면과 데일리 내 탭을 전환할 수 있고, 저장한 값을 새로고침한 뒤에도 읽을 수 있다.

### 2 오늘의 루틴 추가와 완료

- 데일리 루틴 탭에 추가 기능을 만든다. 시간 또는 문구 중 하나, 루틴 내용, 반복 요일 한 개 이상을 입력받는다. `RT-01`
- 오늘 요일에 해당하는 루틴을 등록한 순서대로 보여준다. 시각이 늦거나 문구를 사용해도 순서는 유지한다. `RT-02`
- 체크하면 오늘 날짜의 완료 기록을 저장하고, 해당 항목에 회색과 취소선, 체크 표시를 적용한다. 다음 반복일에는 미완료로 표시한다. `RT-03`
- **완료 기준** — 월·수·금 루틴은 화요일에 표시되지 않는다. 월요일의 체크는 수요일로 이어지지 않으며, 월요일에 앱을 새로 열면 완료 상태가 유지된다.

### 3 할 일 등록과 데일리 완료

- 이름, 색상, 마감 날짜와 시간을 입력받아 저장하는 양식을 만든다. 이 단계에서는 양식과 저장 동작을 검증하고, 4단계에서 월간 캘린더의 추가 버튼에 연결한다. `PL-01`
- 데일리의 할 일 탭에는 오늘과 이후에 마감하는 할 일을 마감 날짜·시간 오름차순으로 표시한다. 마감 시각이 지나도 마감일 당일에는 조회·완료할 수 있고, 다음 날 데일리에서 숨긴다. `PL-05`
- 완료 상태와 실제로 체크한 시각을 저장한다. 완료된 항목은 마감일 당일까지 완료 상태로 표시한다. `PL-06`
- **완료 기준** — 마감이 가까운 항목이 먼저 보인다. 당일 마감 시각 이후에도 체크할 수 있고, 다음 날에는 데일리에서 빠진다.

### 4 할 일용 월간 캘린더

- 이번 달을 기본으로 보여주고 이전 달과 다음 달로 이동할 수 있게 한다. 날짜를 선택하면 해당 날짜에 마감하는 할 일의 상세 목록을 확인할 수 있다. `UI-02`, `PL-03` 일부
- 선택한 날짜를 등록 양식의 기본 마감일로 사용한다. 할 일의 이름과 지정 색상을 마감일 칸에 표시한다. 날짜 상세 목록에서는 완료 상태도 확인한다.
- 데일리와 캘린더는 같은 할 일 기록을 사용한다. 마감일이 지난 항목도 캘린더에서 계속 조회할 수 있다.
- **완료 기준** — 캘린더에서 추가한 할 일이 데일리에 나타나고, 데일리에서 체크한 상태가 캘린더에도 반영된다. 이전 달의 기록도 월을 이동해 확인할 수 있다.

### 5 퀘스트 판정과 보상 지급

- 루틴을 날짜별로 완료할 때와 할 일을 마감 시각 전에 완료할 때 각각 퀘스트 1회를 완료한다. 할 일은 마감 시각과 같은 시각부터 보상 대상에서 제외된다. `GR-01`
- 첫 번째 보상 대상 완료에는 **알 1개**, 두 번째부터 매 완료에는 **먹이 1개**를 자동 지급한다. 지급 내역은 완료 동작 직후 화면에서 확인할 수 있게 한다. `GR-02`
- 루틴은 같은 루틴의 같은 날짜에 한 번, 할 일은 항목당 한 번만 보상을 지급한다. 완료 상태와 지급 내역을 함께 저장하여 연속 클릭이나 새로고침으로 재지급되지 않게 한다.
- **완료 기준** — 첫 유효 완료에는 알만, 두 번째 유효 완료에는 먹이만 지급된다. 마감 시각과 같은 시각이나 그 이후에 체크하면 완료 상태는 저장되고 보상은 지급되지 않는다.

### 6 알 부화와 몬스터 먹이 주기

- 데일리 상단에 알을 받기 전, 알을 받은 뒤, 몬스터가 부화한 뒤의 상태를 보여준다. 알과 몬스터는 각각 한 종류를 사용한다. `GR-03`
- 보유 먹이가 1개 이상일 때 알에 먹이 1개를 사용하면 즉시 부화한다. 부화하면 알 이미지가 몬스터 이미지로 바뀐다. 먹이가 없을 때는 먹이 주기를 사용할 수 없다.
- 부화한 몬스터에게 먹이를 주면 보유 먹이 1개를 차감하고 몬스터에게 먹인 횟수를 1회 늘린다. 부화에 사용한 먹이는 이 횟수에 포함하지 않는다.
- **완료 기준** — 부화와 첫 먹이 주기를 거치면 화면에 몬스터와 `먹인 횟수 1회`가 표시되고, 새로고침해도 먹이 잔량과 상태가 유지된다.

### 7 iPhone과 Windows 사용 검증

- 정적 HTTPS 주소에서 iPhone Safari와 Windows Edge 또는 Chrome으로 이용할 수 있게 한다. 초기 접속 후 오프라인에서도 앱 화면과 로컬 기록을 열 수 있도록 화면 파일, 글꼴과 이미지를 캐시한다. iPhone에서는 홈 화면에 추가한 뒤에도 확인한다.
- 새 데이터로 전체 흐름을 검증한다. 보상 대상 완료를 차례로 세 번 만들고 첫 완료에서 알, 두 번째에서 먹이 1개를 받아 부화, 세 번째에서 받은 먹이 1개를 몬스터에게 사용한다. 루틴 완료와 마감 전 할 일 완료를 각각 한 번 이상 포함한다.
- **Phase 1 완료 기준** — 두 기기에서 각각 위 흐름이 끝까지 동작한다. 인터넷을 끄고 앱을 다시 열어도 해당 기기의 루틴, 할 일, 몬스터와 먹이 기록이 유지된다.
