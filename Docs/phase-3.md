# TimeManager Phase 3 개발 로드맵

Phase 3에서는 월간 캘린더에 등록한 일정을 수정하고 삭제할 수 있게 한다. 일정 변경은 월간 캘린더와 선택 날짜의 상세 목록에 함께 반영하며, 브라우저를 다시 열어도 유지된다. [Phase 2 개발 로드맵](./phase-2.md) · [기능 요구사항](./feature-requirements.md)

## Phase 3 범위

| 기능 | 사용자 동작 |
| --- | --- |
| 일정 수정 | 날짜 상세에서 일정을 열어 이름, 표시 색상, 기간, 종일 여부와 시작·종료 시간을 수정한다. |
| 일정 삭제 | 날짜 상세에서 일정 이름을 확인한 뒤 해당 일정 전체를 삭제한다. |

몬스터 성장 단계는 후속 Phase 후보로 둔다.

## 개발 순서

### 1 날짜 상세에서 일정 수정

- 일정 행에 수정 버튼을 추가한다. 일정 추가 양식을 재사용하고 저장된 값으로 채운다. 선택한 날짜가 여러 날에 걸친 일정의 중간 날짜여도 실제 시작일과 종료일을 보여준다.
- 기존 일정의 ID를 유지하면서 입력값을 갱신한다. 저장이 성공하면 달력의 기존 날짜에서 일정을 제거하고 새 기간에 표시한다. 같은 일정이 날짜별로 복제되지 않도록 하나의 기록을 참조한다. `PL-02`~`PL-04`
- 등록과 수정에 같은 날짜 검증을 적용한다. 종일 일정은 종료일을 포함하며 시작일과 종료일이 같아도 유효하다. 시간 지정 일정은 종료가 시작보다 늦아야 하며, 종료 시각이 자정이면 종료일 칸에서 제외한다.
- 종일과 시간 지정을 전환하면 입력란과 달력 표시가 선택한 유형을 따른다. 날짜 범위가 잘못됐거나 저장이 실패하면 수정 화면에 이유를 표시하고 입력값과 기존 저장 기록을 보존한다. 수정 화면에서 취소하면 저장된 일정으로 돌아간다.
- **완료 기준** — 월을 넘기는 기존 일정을 옮기거나 종일로 변경하면 새 기간과 유형이 달력과 상세 목록에 반영된다. 새로고침 후에도 변경 내용이 유지된다.

### 2 일정 삭제

- 날짜 상세의 일정 행에 삭제 버튼을 추가한다. 확인 단계에서 일정 이름을 표시한다.
- 삭제를 확인하면 하나의 일정 기록을 제거한다. 여러 날 일정은 어느 날짜에서 삭제하든 해당하는 모든 날짜와 상세 목록에서 사라진다.
- 확인을 취소하면 일정이 남는다. 저장에 실패하면 오류를 표시하고 일정은 달력과 상세 목록에 남는다.
- **완료 기준** — 여러 날 일정의 중간 날짜에서 삭제해도 다른 달에 남은 표시가 없으며, 새로고침 후에도 삭제가 유지된다.

### 3 회귀 테스트와 로컬 확인

- 기능을 구현해 커밋하고, 자동 테스트와 Given–When–Then 시나리오는 별도 커밋에 담는다. PR에서 `node --test`로 기존 테스트와 새 테스트를 함께 실행한다. 실패 시 원인, 영향, 수정안을 사용자에게 검토받고 수정 후 다시 실행한다. [프로젝트 작업 지침](../AGENTS.md) · [테스트 시나리오](./test-scenarios.md)
- Windows에서 로컬 확인 링크를 열어 일정 등록·수정·삭제와 새로고침 후 저장 결과를 확인한다. 사용자도 같은 링크에서 기능을 확인할 수 있게 한다. 사용자 확인과 명시적 병합 승인, PR 검사 통과 후 `main`에 병합한다.
- 병합 후 배포된 웹앱에서 최신 버전이 제공되는지 확인한다. Windows 브라우저와 iPhone Safari에서 기존 일정이 업데이트 후에도 열리고 수정·삭제된 결과가 다시 실행해도 유지되는지 확인한다.
- **완료 기준** — 전체 자동 테스트가 통과하고 사용자 확인을 거친다. 배포 후 기기별 확인 결과를 기록한다.

## 추가할 Given When Then 시나리오

| 시나리오 | Given | When | Then |
| --- | --- | --- | --- |
| 월을 넘기는 일정 이동 | 월말부터 다음 달까지 이어지는 일정이 있다. | 중간 날짜의 상세에서 수정 화면을 열고 기간을 다른 날짜로 옮긴다. | 양식에는 실제 시작일·종료일이 표시되고, 저장 후 이전 날짜에서는 빠지며 새 기간에만 표시된다. |
| 종일 전환과 자정 종료 | 밤에 시작해 다음 날 자정에 끝나는 시간 지정 일정이 있다. | 같은 날짜 범위를 유지한 채 종일로 바꾼다. | 변경 전에는 빠져 있던 종료일에 종일 일정이 표시된다. |
| 잘못된 기간 | 유효한 시간 지정 일정이 저장되어 있다. | 종료 시각을 시작과 같거나 더 이르게 바꾸고 저장한다. | 오류가 표시되고 수정값과 마지막으로 저장된 일정이 각각 유지된다. |
| 삭제 확인 | 두 달에 걸쳐 표시되는 일정이 있다. | 중간 날짜에서 삭제 확인을 취소한 후 다시 열어 삭제를 승인한다. | 취소 직후에는 일정이 남고, 승인한 뒤에는 두 달 모두에서 사라진다. |
| 저장 실패 | 기존 일정이 있으며 기기 저장 작업이 실패한다. | 일정을 수정하거나 삭제한다. | 오류가 표시되고 기존 일정이 유지된다. 수정 화면에는 입력값이 남는다. |
| 다시 열기 | 일정 하나를 수정했고 다른 일정 하나를 삭제했다. | 저장된 데이터로 앱을 다시 연다. | 수정한 일정만 변경된 상태로 조회된다. |
