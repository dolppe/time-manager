# TimeManager Phase 2 개발 로드맵

Phase 2에서는 월간 캘린더에 종일 일정과 시간 지정 일정을 추가한다. 사용자는 루틴과 할 일을 수정하거나 삭제하고, 잘못 표시한 완료를 취소할 수 있다. 완료를 취소해도 이미 받은 보상은 유지되며, 같은 할 일이나 같은 날짜의 루틴을 다시 완료해도 지급한 보상을 한 번 더 받지 않는다.

Phase 1에서 저장한 루틴, 할 일, 완료 기록, 보상, 먹이와 몬스터 데이터를 그대로 읽을 수 있어야 한다. [기능 요구사항](./feature-requirements.md) · [Phase 1 개발 로드맵](./phase-1.md)

## Phase 2 범위

| 화면 | 제공 기능 |
| --- | --- |
| 데일리 루틴 | 등록한 루틴의 내용, 시간 또는 문구, 반복 요일 수정. 루틴 삭제와 오늘 완료 취소. |
| 데일리 할 일 | 표시 중인 할 일의 수정, 삭제, 완료 취소. |
| 월간 캘린더 | 종일·시간 지정 일정 등록과 조회. 할 일과 일정 구분 표시. 선택 날짜의 할 일 수정과 삭제. |
| 퀘스트와 육성 | 완료 상태와 이미 지급한 보상 기록을 구분해 관리하고 재완료 시 중복 지급을 방지. |

일정 수정과 삭제, 예약 알림, 기기 간 동기화, 몬스터 성장과 보상 확장은 후속 후보로 둔다.

## 개발 순서

### 1 일정 저장과 등록

- 기기 저장 데이터에 일정 목록을 추가한다. 일정 목록 필드가 없는 Phase 1 데이터는 빈 일정 목록으로 읽고 나머지 기록을 보존한다.
- 월간 캘린더의 선택 날짜에서 일정 등록을 열 수 있게 한다. 이름, 표시 색상, 시작일과 종료일, 종일 여부를 입력받는다. 시간 지정 일정에서는 시작 시각과 종료 시각도 입력받는다. `PL-02`, `PL-04`
- 종일 일정은 시작일과 종료일이 같아도 저장할 수 있다. 종료일이 시작일보다 빠르면 입력 오류를 표시한다. 시간 지정 일정은 종료가 시작보다 늦어야 한다.
- **완료 기준** — 하루 종일, 여러 날 종일, 하루 안의 시간 지정, 날짜를 넘기는 시간 지정 일정을 저장할 수 있다. 잘못된 날짜 범위는 저장되지 않고 입력값은 유지된다.

### 2 월간 캘린더에 일정 표시

- 할 일은 마감일 칸에, 일정은 해당하는 날짜 칸에 이름과 지정한 색상으로 표시한다. 일정과 할 일은 색이 같아도 유형 표시로 구분한다. 선택 날짜의 상세 목록에서 일정 시간이나 종일 여부와 할 일의 마감·완료 상태를 확인할 수 있게 한다. `UI-02`, `PL-03`
- 종일 일정은 시작일부터 종료일까지 양쪽 날짜를 포함한다. 시간 지정 일정은 실제로 걸치는 날짜에 표시한다. 예를 들어 밤 10시부터 다음 날 자정까지라면 밤 10시에 시작한 날짜에 표시한다.
- 일정은 완료 체크나 보상 지급 없이 캘린더에서 조회한다. 데일리 할 일 목록의 마감순 정렬과 지난 할 일의 캘린더 조회는 Phase 1 기준을 적용한다.
- **완료 기준** — 월말에 시작해 다음 달에 끝나는 일정은 두 달에서 조회할 수 있다. 같은 날짜의 할 일과 일정은 구별되고, 일정 등록으로 보상이나 먹이 수량이 달라지지 않는다.

### 3 루틴과 할 일 수정 및 삭제

- 루틴은 내용, 시간 또는 문구, 반복 요일을 수정할 수 있게 한다. 수정 시 항목 ID, 등록 순서와 기존 날짜별 완료 기록을 보존한다. 요일을 변경하면 저장 직후 새 규칙에 따라 오늘 목록을 갱신한다. `RT-01`~`RT-03`
- 할 일은 이름, 색상, 마감 날짜와 시간을 수정할 수 있게 한다. 마감 변경은 데일리 정렬·표시와 캘린더의 날짜 배치에 즉시 반영한다. 이미 완료된 할 일의 완료 시각과 기존 보상 판정은 수정만으로 다시 계산하지 않는다. `PL-01`, `PL-03`, `PL-05`, `PL-06`
- 삭제 전에 항목 이름을 보여주고 확인을 받는다. 삭제한 루틴은 반복 목록에서 빠지고, 삭제한 할 일은 데일리와 캘린더 양쪽에서 빠진다. 이미 지급된 보상과 그 보상으로 진행한 부화·육성은 유지한다.
- **완료 기준** — 루틴을 수정해도 순서가 바뀌지 않는다. 할 일 마감일을 옮기면 두 화면에 동일하게 반영된다. 삭제 확인을 취소하면 항목이 유지되고, 삭제를 완료하면 다시 열어도 해당 항목이 나타나지 않는다.

### 4 완료 취소와 중복 보상 방지

- 데일리에서 오늘 완료한 루틴과 목록에 표시되는 완료된 할 일의 완료를 취소할 수 있게 한다. 취소한 할 일은 이전 완료 시각을 지우고, 다시 완료하면 새 완료 시각을 기록한다. `RT-03`, `PL-06`
- 보상 지급 여부는 루틴 ID와 날짜의 조합 또는 할 일 ID로 확인한다. 완료 취소, 항목 수정과 새로고침을 거쳐도 이미 지급한 보상 기록을 유지한다. 보상을 받은 적 없는 할 일을 다시 완료할 때는 그 시점의 마감을 기준으로 판정하며, 마감 시각 전의 완료만 보상 대상이다. `GR-01`, `GR-02`
- **완료 기준** — 보상을 받은 뒤 취소하고 다시 완료해도 보상 수량은 증가하지 않는다. 먹이를 이미 사용한 경우에도 부화 여부와 먹인 횟수가 유지된다. 다음 반복일의 루틴 완료는 그날의 보상 조건을 새로 판정한다.

### 5 기존 기능과 배포 환경 검증

- 각 기능 브랜치의 PR에서 새 테스트와 기존 테스트를 포함해 `node --test`를 실행한다. 실패 시 원인, 영향 범위와 수정안을 사용자에게 검토받은 뒤 수정하고 전체 테스트를 재실행한다. [테스트 시나리오와 검토 절차](./test-scenarios.md)
- 배포된 HTTPS 주소에서 Windows 브라우저와 iPhone Safari의 일정 등록, 항목 수정·삭제, 완료 취소를 확인한다. iPhone 홈 화면에서 다시 실행하고, 첫 접속이 끝난 뒤 오프라인에서도 기록을 열 수 있는지 확인한다.
- **완료 기준** — Phase 1 데이터로 시작해 새 기능을 사용한 뒤에도 기존 완료 기록, 보상과 육성 상태가 보존되고, PR의 전체 자동 테스트와 두 기기의 확인 시나리오를 통과한다.

## 추가할 Given When Then 시나리오

| 시나리오 | Given | When | Then |
| --- | --- | --- | --- |
| 기존 데이터 읽기 | 일정 목록 필드가 없는 Phase 1 저장 데이터가 있다. | Phase 2 앱을 연다. | 기존 항목과 몬스터 상태를 읽고 새 일정을 저장할 수 있다. |
| 일정 범위 검증 | 시작 시각이 오후 3시다. | 같은 날 오후 2시나 오후 3시를 종료 시각으로 저장한다. | 저장이 거절되고 입력이 유지된다. |
| 월 경계의 일정 | 월말 밤부터 다음 달 아침까지의 일정과 같은 색의 할 일이 있다. | 두 달의 캘린더를 연다. | 일정이 해당 날짜 모두에 표시되고 할 일과 구분된다. |
| 루틴 수정 | 월요일에 완료한 반복 루틴이 있다. | 내용과 반복 요일을 수정한다. | 등록 순서와 월요일 완료·보상 기록이 유지되고 이후 목록은 새 요일 규칙을 따른다. |
| 할 일 수정 및 삭제 | 오늘 마감인 할 일이 두 화면에 보인다. | 마감일을 바꾼 뒤 삭제한다. | 두 화면이 새 마감을 반영하고 삭제 후에는 두 화면에서 사라진다. |
| 완료 취소 후 재완료 | 마감 전에 완료해 보상을 받은 할 일 또는 당일 루틴이 있다. | 완료 취소 후 앱을 다시 열고 같은 항목을 다시 완료한다. | 완료는 기록되며 보상은 최초 지급분만 남는다. |
| 취소 저장 실패 | 완료와 보상 이력이 저장되어 있다. | 완료 취소 중 저장이 실패한다. | 기존 완료 상태, 보상과 육성 상태 모두 그대로 유지된다. |
